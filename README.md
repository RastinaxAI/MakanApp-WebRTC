# زیرساخت WebRTC ماکان

این مخزن شامل سورس صفحهٔ مستقل تست LiveKit، ابزارهای استقرار و بررسی سرور و دو سند نهایی تحویل است.

نشانی اتصال کلاینت: `wss://195.177.255.98:8443`

صفحهٔ مستقل تست: [باز کردن صفحه](https://195.177.255.98:8443/webrtc/)

بک‌اند اصلی ماکان، نشست و مجوز تماس و صدور توکن کاربران را مدیریت می‌کند. این مخزن به‌تنهایی قابلیت تماس داخل نسخهٔ آنلاین برنامه را منتشر نمی‌کند. ابزار دعوت، مخصوص آزمون زیرساخت توسط مدیر سرور است.

## فایل‌های اصلی

| مسیر | کاربرد |
| --- | --- |
| `deploy/webrtc-page/` | سورس HTML، CSS و JavaScript صفحهٔ مستقل تست |
| `deploy/makan-webrtc-invite.py` | ساخت دعوت موقت توسط مدیر مجاز سرور |
| `deploy/*.sh` | اسکریپت‌های بررسی، آماده‌سازی، استقرار و بازگشت |
| `deploy/*.py` و `deploy/*.cjs` | ابزارهای SSH و آزمون شبکه و رسانه |
| `scripts/prepare-sdk.cjs` | آماده‌سازی SDK و مجوز آن از وابستگی نصب‌شده |
| `Makan_Implementation_Guide_FA.pdf` | راهنمای پیاده‌سازی محصول؛ ۸ صفحه |
| `Makan_Backend_WebRTC_Connection_FA.pdf` | راهنمای فنی اتصال بک‌اند؛ ۱۳ صفحه |

دو PDF در ریشهٔ همین پروژه قرار دارند. پوشهٔ `repos` نسخهٔ محلی یک پروژهٔ دیگر و دارای تغییرات مستقل است؛ در این مخزن ثبت نمی‌شود. پوشه‌های خروجی، وابستگی‌های نصب‌شده، فایل‌های موقت و کلیدها نیز خارج از Git هستند.

## آماده‌سازی ابزارها

برای ابزارهای مرورگر، Node.js نسخهٔ ۲۰ یا جدیدتر لازم است:

```text
npm ci
npm run prepare:sdk
```

SDK نسخهٔ 2.23.0 و مجوز آن در پوشهٔ صفحه آماده می‌شوند؛ این دو فایل تولیدی وارد Git نمی‌شوند و هنگام بارگذاری صفحه روی سرور باید همراه فایل‌های صفحه منتقل شوند. نصب وابستگی‌ها استقرار خودکار ندارد.

ابزارهای مرورگر به‌صورت پیش‌فرض Chrome نصب‌شده را مصرف می‌کنند. برای Chromium می‌توان `MAKAN_BROWSER_CHANNEL=chromium` تنظیم و مرورگر لازم را با `npx playwright install chromium` نصب کرد.

برای ابزارهای Python، در محیط مجازی جداگانه وابستگی‌ها را نصب کنید:

```text
python -m venv .venv
python -m pip install -r requirements.txt
```

فرمان دوم را پس از فعال‌کردن محیط مجازی، یا با Python همان محیط اجرا کنید. نسخه‌های Python در این فایل قفل نشده‌اند؛ پیش از استفادهٔ عملیاتی، سازگاری پکیج‌ها و کتابخانهٔ native رسانه با محیط مقصد بررسی شود.

## اجرای عملیات سرور

اسکریپت‌های استقرار با وضعیت ثبت‌شدهٔ VPS و مسیرهای نگهداری اکتبر ۲۰۲۶ نوشته شده‌اند؛ پیش از استفاده روی سرور دیگر یا اجرای دوباره، پیش‌شرط‌ها و مسیرهایشان بازبینی شوند. اجرای آماده‌سازی محلی، مجوز اجرای همهٔ اسکریپت‌ها روی سرور نیست.

ابزارهای SSH از `known_hosts` استفاده می‌کنند و رمز را هنگام اجرا می‌پرسند. کلید و Secret رسانه فقط در تنظیمات محافظت‌شدهٔ سرور و بک‌اند باقی بمانند. رمز SSH، JWT و لینک دعوت خصوصی را وارد Git نکنید.

تست‌ها ممکن است هنگام اجرای صریح، پوشهٔ `output` ایجاد کنند؛ این پوشه در Git نادیده گرفته می‌شود. بعضی مراحل تاریخی به فایل مبنای همان اجرای استقرار نیاز دارند؛ حذف خروجی‌های قبلی به معنی قابل اجرای دوباره بودن تمام مراحل بدون آماده‌سازی نیست.

## گیت

فهرست فایل‌های انتخاب‌شده را با `git diff --cached --stat` و `git diff --cached --name-only` بررسی کنید. برای ثبت محلی، پس از بررسی از `git commit` استفاده کنید. نشانی remote باید مربوط به همین مخزن زیرساخت باشد؛ remote بک‌اند از پوشهٔ `repos` به این پروژه منتقل نشده است.
